EFFECT JOBS / GUIDE

Reading durable jobs.

Metadata explains durable work; it cannot prove every external effect.

States, attempts and policy

Pending waits for eligibility. RetryScheduled waits after a finalized retry. Active is owned by a worker. Completed, Dead and Isolated are durable lifecycle states. Isolated is never automatically purged.

Finalized attempts are not a complete execution history. Unknown recovery may repeat an attempt number. Lease duration is persisted policy, not proof of current ownership; lease tokens and expiry are unavailable in the public detail API.

Availability is not a deadline or a promise of execution at that time. Policy is persisted with the job; new deployment defaults do not rewrite it. Retention can remove deduplication evidence.

Current pages and live reads

Combine exact state and kind filters. The API orders by job ID ascending with an opaque cursor. Search, due-Pending view and counters describe the current page only. Due uses the browser clock and is not an authoritative DB-time eligibility check.

Pages are current reads, not historical snapshots. State changes can move rows across pages. Refresh preserves filters, cursor and selection. Invalid cursors require an explicit First page action. Sandbox generation changes revoke old data and selection while preserving filters.

Visible pages reconcile reads every five seconds. Reconnect causes a fresh read. Stale state labels the last successful data as potentially outdated. Global search, alternative sorting, total counts and lease-expiry filters are unavailable.

Unknown outcomes and scenarios

A lost response does not prove rollback or success. An unknown command keeps its exact request identity and disables further commands. Check exact request receipt is read-only; receipt absence does not authorize replay.

Acknowledged enqueue does not prove handler success or exactly-once external effects. The scenario launcher uses synthetic provider behavior with 1–10 jobs per request. No live email, payment or outbound webhook is sent.

Reset changes your sandbox generation and visibility. It does not cancel running jobs or bypass their lease and finalization protocol. Capability flags are hints; the server independently checks authority, origin, CSRF and quotas. Unsupported retry, cancel and redrive controls remain disabled.

Privacy, isolation and evidence

List and detail responses expose allowlisted metadata and synthetic application relations only. Payload, ciphertext, fingerprints, protected fields, credentials and raw provider errors are unavailable. Synthetic entity links are examples, not external accounts.

Source labels distinguish mock UI fixtures from local, workerd and hosted observations. Missing observations mean unknown. Fixtures provide no durable jobs, authentication or execution qualification. Hosted integration must use real jobs and a server-owned credential cookie.

The frozen API has no shared public feed; your private sandbox is never silently published as one. Unknown command identity is kept only for this mount. Reloading loses this UI memory; server receipts and authority remain the integration owner's responsibility.
